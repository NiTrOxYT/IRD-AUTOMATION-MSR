## 1. Executive Summary & Goals

The goal of this initiative is to introduce a production-grade, highly resilient **DTH Channel Configuration Automation** module into the existing `C:\IRD AUTO` automation platform. 

The module automates bulk channel creation inside the legacy/enterprise ZMP portal via Playwright browser interactions. It avoids manual portal form data entry while strictly maintaining:
1. **Zero disruption to existing IRD synchronization:** All IRD menus, tunnels, workflows, database models, and scheduled tasks remain 100% untouched and functional.
2. **CREATE-ONLY Safety:** Will never overwrite, delete, renumber, or corrupt existing channels in the portal.
3. **Mandatory Category Assignment:** Enforces assignment to category `all` alongside requested categories.
4. **Resilient Browser Automation:** Implements selector abstraction, retry safety, state reconciliation, and session recovery.
5. **Preflight Validation & Dry-Run by Default:** Guarantees zero portal mutations during dry runs and preview checks.

## 4. Input File Schema & Business Rules

### 4.1 Canonical Schema
Supported formats: `.csv` (UTF-8, UTF-8-BOM) and `.xlsx` (OpenPyXL).

| Column | Type | Required | Description | Constraints |
|---|---|---|---|---|
| `channel_number` | String/Int | Yes | Target channel number / LCN | Must be non-empty, alphanumeric or positive integer |
| `name` | String | Yes | Display channel name | 1-100 characters, whitespace normalized |
| `osd` | String | Yes | On-Screen Display name | 1-50 characters |
| `image` | String | Yes | Logo filename or relative path | Must exist in selected image directory |
| `categories` | String | Yes | Comma-delimited category list | Normalized, trimmed |

### 4.2 Mandatory Category Assignment Rule
1. **Always Include `all`:** Every channel will be assigned to category `all`, regardless of whether it is listed in the input file.
2. **Add Explicit Categories:** Split input by commas, trim whitespace, deduplicate case-insensitively.
3. **Validation Against Portal:** Check category names against the portal's available category registry.
4. **Formula:** `final_categories = ["all"] + [c for c in requested_categories if c.lower() != "all"]`.

### 4.3 Safe Image Handling
- Users specify an image directory path (or upload zip/files).
- Directory path is validated to prevent path traversal (`..` resolution checks).
- No external HTTP(S) URL downloads allowed.
- Image files must exist on disk and be valid image extensions (`.png`, `.jpg`, `.jpeg`, `.bmp`, `.webp`).

## 5. Duplicate Protection & Safety Policies

1. **CREATE ONLY Policy:**
   - The automation will never click edit, update, delete, or overwrite on an existing channel.
2. **Preflight File Duplicate Detection:**
   - Duplicate `channel_number` within input file → Flagged as `INVALID`.
   - Duplicate `name` within input file → Flagged as `INVALID`.
3. **Portal Duplicate Detection:**
   - Queries portal channel list before filling form.
   - If channel number or name matches an existing record → Mark as `SKIPPED_DUPLICATE` without mutating portal.
4. **Reconciliation on Ambiguity:**
   - If a submission encounters a timeout or connection glitch, the outcome is marked `UNKNOWN`.
   - The controller queries the channel listing to verify whether the channel was saved before deciding next action.

## 6. Execution State Machine

```
[INPUT FILE] 
      │
      ▼
   PARSING ──(Syntax Error)──► INVALID
      │
      ▼
 PREFLIGHT VALIDATION ──(File Duplicates / Missing Fields)──► INVALID
      │
      ▼
   DRY RUN (Default) ──► PREVIEW / DRY RUN REPORT (Zero Mutations)
      │
      ▼ (Explicit User Authorization Required)
  START LIVE RUN
      │
      ├── Channel N: PENDING
      │        │
      │        ▼
      │    CHECKING PORTAL DUPLICATE ──(Already Exists)──► SKIPPED_DUPLICATE
      │        │
      │        ▼
      │    FILLING FORM & UPLOADING LOGO
      │        │
      │        ▼
      │    ASSIGNING CATEGORIES ("all" + requested)
      │        │
      │        ▼
      │    SUBMITTING FORM
      │        │
      │        ├── Success Verified ──► SUCCESS
      │        ├── Portal Rejection ──► FAILED
      │        └── Timeout / Dropped ──► UNKNOWN (Reconcile)
      │
      └── (User Stop Requested) ──► CANCELLED (Safe halt after current step)
```

## 7. Security & Credential Protection

- **No Secrets in Logs:** Credentials, session cookies, and bearer tokens are never logged or exposed in audit trails.
- **DPAPI Credential Storage:** Reuses existing Windows DPAPI / Fernet infrastructure for storing site credentials.
- **Filesystem Traversal Prevention:** Strict `Path.resolve().is_relative_to(base_dir)` checks for all file and image paths.
- **Role & Action Isolation:** Live execution requires an explicit POST confirmation payload.

## 9. Risks, Assumptions & Unverified Elements

- **Unverified Portal Selectors:** Because the live ZMP portal is not actively connected to this dev environment, exact CSS/XPath selectors and DOM structures are unverified. They are isolated in `app/dth_automation/selectors.py` and stored in SQLite so they can be adjusted in the UI or configuration without touching code.
- **Portal Response Speed:** ZMP portal forms may experience latency during image uploads; controller uses explicit condition waits rather than fixed sleeps.
- **Assumption:** Channel numbers are alphanumeric strings (preserving leading zeros where necessary).
